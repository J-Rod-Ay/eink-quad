# Quad Board on the reTerminal E1003

The E1003 replaces the E1001. Both stay supported: the PlatformIO env picks the
model, and the server's `QUAD_MODEL` env var picks the render profile.

| | E1001 (env `quad`) | E1003 (env `quad-e1003`) |
|---|---|---|
| Panel | 7.5" UC8179, 800×480 | 10.3" ED103TC2 behind an IT8951-class TCON, 1872×1404 |
| Grey | 4 levels, 2bpp on the wire | 16 levels, 4bpp on the wire (2 px/byte, even x high nibble, 0=black..15=white) |
| Seeed_GFX setup | 520 | 522 (`Setup522_Seeed_reTerminal_E1003.h`) |
| 1-bit buffer | 48,000 B | 328,536 B |
| Grey frame | 96,000 B | 1,314,144 B (whole reel ≈ 1.64 MB, under the 3 MB `MAX_REEL`) |
| LED | GPIO6 | GPIO16 (active low) |
| Battery | ADC GPIO1, enable GPIO21 | ADC GPIO1, enable **GPIO40** (GPIO21 powers the TCON) |
| Home | `quad` 2×2 / `six` 3×2 | `nine` 3×3 (default), also quad/six |

## Orientation and resolution
Landscape, 1872 wide × 1404 tall, rotation 0 (same as Seeed's examples). The server
lays out a 1040×780 board and draws it at K = 1.8 px per unit, roughly the dpi
ratio (about 227 vs 125). It scales every coordinate, stroke, font size, icon and
logo before drawing. Glyphs are hinted at their real size, so nothing gets
upscaled, and the header and strip keep the same physical size as on the E1001.
The E1001 output is byte-identical to before (checked for quad, six, grey and
detail pages).

Default E1003 slots (left column = sports side): sports, weather, news,
scoreboard, sky, shabbat, shopping, calendar, trips. Shopping is a new compact corner panel. It
also counts as a corner on the E1001, but it sorts last, so nothing picks it by
default.

## Pins (from Setup522)
EPD: SCLK 7, MISO 8, MOSI 9, CS 10, DC -1, BUSY/HRDY 13, RST 12, ENABLE 11,
ITE_ENABLE 21 (Seeed_GFX owns it, so don't touch it). Buttons KEY0/1/2 = GPIO3/4/5,
the same as on the E1001. One community pin map lists GPIO4 as the centre button.
If the button roles feel swapped, remap them in board.h. Buzzer 45, SHT4x on I2C
19/20, SD enable 39.

## Touch (GT911): not used in v1
I2C SDA 19 / SCL 20 (shared with the SHT4x), INT GPIO2, RST GPIO48, address 0x5D
(or 0x14, depending on the INT level at reset). The pins are in `board.h`, but the
firmware doesn't drive the controller yet. Next step: set up a GT911 poll that
logs taps, then map taps on the 3×3 grid to `btn`/page requests (tap a slot to open
its detail page).
For deep sleep, hold GPIO48 low so the touch chip doesn't float and drain power.

## Build / flash (Zev's Mac)
```
cd firmware
pio run -e quad-e1003                       # build
pio run -e quad-e1003 -t upload             # flash (only after Zev approves)
pio device monitor -b 115200
```
`pio run -e quad` still builds the E1001.

Serial: the E1003 USB bridge is a WCH CH343. On macOS, install WCH's CH34x/CH343
VCP driver (wch-ic.com → CH343SER_MAC) and approve it under System Settings →
Privacy & Security. Then the port shows up as `/dev/cu.wchusbserial*`. Pass it
with `--upload-port` if pio picks the wrong one. If upload won't start, hold
KEY0/BOOT while you plug in.

## Server
Run with `QUAD_MODEL=e1003` (the default is e1001). If an existing `state.json` or
config already has `layout: quad`, it is kept. Set `layout=nine` in settings, or
remove the key, to get the 3×3 home. Firmware sends `&m=e1003` / `&m=e1001` on
every poll for logging.

Preview: `cd server && python3 e1003_preview.py /workspace/quad-vm/e1003-home-preview.png`
(uses live public feeds, with fixtures for calendar, TripIt, shopping and sky).

## Deploy rule
Nothing has been flashed or deployed. The firmware flash and the GCP `QUAD_MODEL=e1003`
switch both wait for Zev's approval of the preview PNG. Until then the live server
keeps rendering 800×480, which an E1003 would reject because the frame size
doesn't match.
